# Environment-level agent instructions (`agentInstructions`)

This repository ships one environment-level instruction file for every agent that works under a given `DSH_HOME`. The source of truth is a repository file; `scripts/sync.mjs` materializes it as `$DSH_HOME/AGENTS.md`, which DSH loads natively.

## Why it exists

Tool schemas advertise parameters such as `sandbox_permissions` statically, while the permissions that actually apply come from each session's latest runtime context. A session that is already in `danger-full-access`, or that runs with approvals disabled, can still receive repeated `not strictly wider` errors if the model keeps requesting an escalation. Putting the rule into a custom agent preset would copy the whole official `standard` preset and create a parallel baseline that drifts. A preset is a roster/composition choice, not a place for guidance that every agent in the environment should see.

Environment-level guidance therefore lives in `$DSH_HOME/AGENTS.md`:

- The official `standard` preset loads it automatically, so no preset copy has to be maintained.
- Instructions are decoupled from roster selection; every agent under that `DSH_HOME` sees the same text.
- The single source is `instructions/dsh-home.md`, selected by the top-level `agentInstructions` block of `dsh.yaml`.

The instructions are model guidance. They grant no permission and do not replace the runtime's real safety boundary.

## Manifest contract

```yaml
agentInstructions:
  enabled: true
  source: instructions/dsh-home.md   # repository-relative; absolute paths and paths escaping the repo are rejected
```

`enabled: false` (or removing the block) revokes the managed file; see below.

## How sync materializes it

`syncAgentInstructions` in `scripts/sync.mjs` renders the target as a `# GENERATED by ohmydsh scripts/sync.mjs` header, a `# Source:` line, then the source body. Ownership is tracked in `$DSH_HOME/.dsh-sync-state.json` under `agentInstructions` as `{ source, deployedHash }`.

| Situation | Behavior |
|---|---|
| Source missing, not a file, or resolving outside the repository | sync fails; nothing is written |
| Target absent | generate it with an atomic write (temporary file, then rename) and record the hash |
| Target present but unmanaged, content differs | refuse to overwrite and fail |
| Target present but unmanaged, content equals the desired output | adopt it without rewriting |
| Target managed, content equals the recorded hash, source unchanged | report up-to-date |
| Target managed, content equals the recorded hash, source changed | update atomically |
| Target managed but edited since deployment (hash drift) | refuse to overwrite or delete, and fail |
| `enabled: false` / `--reset`, target managed and unchanged | remove the file and clear the state entry |
| `enabled: false` / `--reset`, target unmanaged | leave it in place |

## Verifying a change

1. `node --test tests/sync-agent-instructions.test.mjs` covers path escape, first deployment, idempotence, unmanaged conflicts, drift, and safe revocation.
2. `node scripts/sync.mjs` against an isolated `DSH_HOME` should leave `$DSH_HOME/AGENTS.md` with the GENERATED/provenance header followed by the source body.
3. `agentInstructions.source` and `agentInstructions.deployedHash` should be present in `$DSH_HOME/.dsh-sync-state.json`.
4. A second `node scripts/sync.mjs` run should report no changes.
