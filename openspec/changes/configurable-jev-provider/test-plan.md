## Coverage Notes

- Existing tests listed with "(updated …)" keep their current assertions (signal/exit propagation, privacy sentinels, ownership/drift/idempotency, retention, concurrency, real-vibe-only admission, legacy v1/v2 read and label) and only change fixtures or expected key sets; they start red because the fixture/key-set update precedes the implementation.
- "A synthetic fixture is recorded" and "Routing is disabled" are existing behaviors; their named tests already exist. They are re-run red-first by adding a `jevProvider` assertion (synthetic record keeps provenance and has `jevProvider`; disabled mode writes nothing even with `jevCalls`).
- Shared fixture: a helper building valid `jevCalls` projections (`success(provider, semantic)` / `error(message)`) in tests/jev-workflow-router.test.mjs.
- Readiness tests run the script against a temporary `DSH_HOME` with zstd-compressed fixture session files and a temporary repo copy of `dsh.yaml`; the script gains a `DSH_REPO_ROOT`-style override only if needed for isolation (decided during apply; no behavior change otherwise).
- Report tests write records directly to the temporary records file (as existing report tests do).
- Out-of-suite acceptance (verify.md, not test-plan rows): `dsh build` twice (second run no changes), Host restart, new session shows `mcp__jev__jev_classify`/`jev_decide`, `node scripts/jev-readiness.mjs` reports `liveProbeReady: true`, one real shadow record with `jevProvider: openrouter`.
