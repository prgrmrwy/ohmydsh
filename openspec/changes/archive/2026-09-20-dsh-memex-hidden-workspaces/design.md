# 设计：把「已关闭记忆」的工作区收起来

## Context

DSH Pet 关掉记忆后，它仍是一个完整的工作区块（标题、路径、入口、兜底行、记忆开关、关闭说明），
与每天要用的 nexus / ohmydsh / flow-web 同权地占着列表位置。本机 8 个工作区已经要滚一屏，
而「关闭了记忆」在功能上就是退出日常视野：不注入召回、不提醒、工具拒绝。

## Goals / Non-Goals

- Goal：不关注的工作区不占主列表的位置，但**仍然可达**——关掉记忆的人必须还能在页面上把它打开。
- Non-Goal：不做通用过滤器/搜索/排序（那是另一个维度的需求）；不动任何配置语义；不改变未关闭工作区的顺序。

## Decisions

### D1. 收起而不是过滤掉

「过滤掉」会让状态不可见也不可逆：页面看不出"有个工作区被我关了"，想恢复只能手改 settings。
收起保留了「存在且有 N 个」这条信息，展开即回到完全一样的编辑形态，因此选择折叠分组。

### D2. 分组放在列表末尾、默认收起

主列表读的是「我现在用哪些工作区」，关闭项属于「我特意停掉的」——语义上是列表的尾部附录，
不是开头也不是中间。默认收起符合"不关注"的原意；数量放在标题里，所以收起也不丢信息。

### D3. 展开状态是纯视图状态

和入口行的展开一样，不进配置、不标脏、不写 settings。没有关闭项时分组整体不渲染，
避免出现一个空的「已关闭记忆 (0)」标题。

### D4. 关闭项内部渲染完全复用同一段代码

分组只负责取舍与折叠，块本身仍走同一条渲染路径（入口、兜底行、记忆开关、关闭说明），
所以"能不能再打开"这件事不依赖任何特殊分支——它本来就在那个块里。

## Risks / Trade-offs

- 收起后**数量变化不易察觉**：新增一个关闭项只会让标题数字 +1。可接受——它本来就是"不关注"的语义，
  而每次关闭动作都发生在用户自己刚操作过的那个块上，切换瞬间该块会移入分组，动作是可见的。
