## Candidate comparison and current decision

| Candidate | Effect and limitation |
|---|---|
| Responses-only `supportsStrictMode:true` | Adopted minimal candidate after bounded local + live acceptance/behavior proof: ordinary Responses functions become explicit false, schemas remain structurally identical; Chat remains unchanged. Raw upstream forwarding was not captured. |
| Enable the flag for both protocols | Unnecessarily adds a field to all Chat backends, where gateways may reject unsupported fields; not needed for this Responses-specific omission. |
| Force all tools strict true / nullable / require every property | Changes the native DSH contract and does not address action-dependent omission; rejected. |
| Patch every wire tool with `onPayload` | Duplicates pi-ai's existing converter and adds a second schema policy; larger and unnecessary if the compat contract is supported. |
| Strip sandbox/goal fields or send empty/null values | Symptom workaround, removes legitimate native declarations or violates action contracts; rejected. |

**Original investigation decision (historical): report-only; adapter unchanged at that stage.** Gateway acceptance evidence was unavailable then. The candidate `.strict === false` assertion failed in three Responses cases and was deliberately replaced by clearly labeled **current-state observation** assertions; that stage's GREEN was schema-preservation/current-omission coverage, **not repair GREEN**. This historical decision and its fixture mistakes remain part of the evidence.

**Current bounded decision:** the subsequent live proof (`openspec/changes/add-dsh-magpie-plugin/gateway-readonly-proof.md:50–65`) plus local SDK/compat evidence is sufficient for the lead-approved **Responses-only** standard-field candidate, without waiting for the unavailable Go source, requiring a new product API or adding a configuration switch. [Adapter model/compat:128–130](<../../../packages/dsh-magpie-connector/src/host/adapter.ts#L128-L130>) now conditionally enables `supportsStrictMode:true`; pi-ai emits ordinary-tool false. Fresh local focused **10/10**, full **30 files /189 tests**, source+test typecheck and local build passed. Independent candidate review, deployment and runtime acceptance remain pending; no main-session symptom closure or all-goal PASS is claimed.
