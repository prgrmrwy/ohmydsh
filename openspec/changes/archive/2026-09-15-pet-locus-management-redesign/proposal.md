## Why

Pet 的 Locus 管理面把**每一条 locus 记录**平铺成一张等权大卡：本机真实快照 4 条 locus 就让该页签达到 3444px（4.2 屏），47 行等权事实、17 处原始 ID、39 个按钮，而每张卡的标题是 `oc_a27b5de7e6a9a57462060eb289ec70ab`。所有者无法据此判断「哪条入口还活着、它连着哪份工作、能不能写」，也就无法做解绑/重建/权限决策——这不是纯视觉问题，是决策依据问题（BACKLOG B026、B030，2026-09-13 已复核确认未实现）。

（上述尺寸与条数取自 2026-09-15 的真实快照，早于主干 `pet-locus-on-demand-tree`；该 change 只改变建树时机、不改变呈现方式，所以同一批关联在这版界面下仍是同样的平铺卡片。）

与此同时，设置页仍保留两类**新建外部资源**的入口：绑定 endpoint 需要手输 chat/thread/session/workspace 裸 id；默认 Q&A 会按裸 session id 并排渲染「创建/打开」按钮，而点击是**不可逆的外部副作用**（真实创建飞书群并指定群主）——B033 已就此定为 P1。

三条 backlog 现均已「已设计」，且本轮范围被所有者明确限定为**纯面板调整**：不新增任何 Host / wire 能力。这使本次改动风险面最小、可独立验收。

## What Changes

- **按入口聚合取代平铺代际**：一行 = 一个 endpoint = 一个 locus 家族。当前代做主行，历史代折叠为「历史 N 代」；同一父会话只渲染一次，其入口挂在下面。
- **显式表达 session 与 locus 的关系**：父会话 → 入口 → 会话 的关系用「关系轨」（1px 竖轨 + 状态节点）承载；节点即状态，不再另立状态胶囊。话题 locus 按 `parentLocusId` 嵌套在群级 locus 之下（该字段旧 UI 从未渲染）。
- **语义化标识**：新增短码体例 `L·2f85 / S·9062 / oc·a27b / omt·19cd / W·d5d2`，由真 ID 确定性派生、点击复制完整 ID、**永不作为请求入参**；所有原始 ID 收进每行「标识符」折叠区。首行不得以 `oc_` / `omt_` / `session-` / `locus-` 开头。
- **名称与短码成对出现**：实测同一父会话下会出现两个「答疑 · DSH」，因此名称单独不构成身份；无名时显示兜底名（有 `threadId` → `话题 · 19cd`，否则 → `入口 · a27b`，不写「群」，因为 `chatType` 未持久化）。
- **双向读法**：`按工作`（父会话 → 入口）与 `按入口`（入口 → 会话/父会话）两个读法共用同一份已下发的 `discovery` 索引，不新增查询。
- **跳转**：每行固定 `会话 ↗ / 飞书 ↗`（按入口读法另有 `父会话 ↗`）；话题行提供话题链接；父会话标题保持链接样式。目标归档/不可达时不可点并给出原因（fail closed）。
- **父会话与入口状态筛选**：默认只显示可用父会话下仍在服务的入口；条件由筛选控件自述（收起态写明两个维度，浮层按桶给出全量计数），列表内不再单起一行"隐藏出口"。
- **默认 Q&A 只读化**：降为行内徽标（蓝环节点 + 文字徽标双通道），不再单独列举。
- **BREAKING（owner-facing，移除设置页的创建入口）**：移除绑定 endpoint 表单；移除默认 Q&A 的两组创建按钮与空态创建入口，改为说明「请在目标会话里用 Pet 轮盘的『答疑群』创建」。替代路径：关联由飞书消息建立，Q&A 由轮盘建立。
- **撤出无意义读数**：`generation 0`（快照 generation，用于客户端变更检测，不是 locus 代际）从面板移除，只留诊断页。
- **不新增任何能力**：群名 / 话题名 / `chatType` 在本轮不引入查询、持久化或刷新动作；面板不在打开时请求飞书接口。

## Capabilities

### New Capabilities

（无。本 change 不引入新 capability。）

### Modified Capabilities

- `pet-locus-collaboration`：所有者管理面的**呈现与可达性**要求变更——按入口聚合与代际折叠、双向读法的呈现、标识与名称规则、跳转与 fail-closed 呈现、父会话与入口状态筛选（条件由筛选控件自述）、默认 Q&A 的只读呈现、管理面不再提供新建外部资源的入口。「关联具备双向发现且不过度披露」与「管理面的会话可用性以持久证据判定」两条既有要求保持其不变量，仅补充呈现层约束。
- `dsh-pet`：「Pet 设置采用固定的页签信息架构」需要修正——该要求现写「固定包含以下五个页签」且未列出 Locus（实现中 `PET_SETTINGS_TABS` 为六个页签，含 `locus`），属规范与实现既存漂移；本次补齐页签枚举并明确 Locus 页签只做展示、导航与生命周期动作，不承载新建外部资源。

## Impact

- **代码（仅 Web 客户端）**：`packages/dsh-pet/src/client/settings.tsx`（`LocusTab` 重写）、`packages/dsh-pet/src/client/styles.ts`（新增关系轨/行/短码/筛选样式）、建议新增 `packages/dsh-pet/src/client/locus-view.ts`（短码派生、家族聚合、分组、筛选等纯函数，便于单测）。
- **测试**：`packages/dsh-pet/test/client.test.ts` 中针对 `settings.tsx` 的大量 source-text 断言需随重写更新，并新增「首行不以原始 ID 开头」「同一 locus 只渲染一次」等断言。
- **不动**：`packages/dsh-pet/src/host/**`、`packages/dsh-pet/src/wire.ts`、Host 路由与持久化。无新增依赖，无协议变更。
- **Owner-facing 入口移除**：设置页不再提供「绑定 endpoint」与「创建默认 Q&A」，替代路径为飞书消息与 Pet 轮盘；对应 backlog B033。
- **与主干 `pet-locus-on-demand-tree` 的关系**：该 change（已归档）把建树时机改为「首条合格消息」，因此管理面只会出现**已建树**的入口，且 `provisioning` 成为真实瞬时态——本 change 不修改其任何行为，只在呈现层如实表达（未建树的入口不出现是正确结果，不是缺失）。实现应基于含该 change 的主干进行，验收需覆盖该交互。
- **来源 backlog**：B026（可辨识性与代际说明）、B030（按入口聚合）、B033（设置页不提供默认 Q&A 创建入口）随本 change 一并实施。
- **不在本次范围**（已在 backlog 记录决定）：群名/话题名/`chatType` 的获取与持久化、飞书回执侧的人类可读标识、B040（归档父会话的入站回执）。
