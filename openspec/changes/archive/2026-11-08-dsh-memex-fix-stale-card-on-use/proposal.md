## Why

2026-10 的两轮记忆库审查发现，卡片过期是记忆失效的主要原因：高风险卡里 58% 需要修订或归档，随机抽样的“低风险”卡里也有 46%。同期的有卡/去卡对照试点显示，卡片准确时调查量约减半；卡片过期时 Agent 会先核验再纠正，不会被带错，但也得不到任何节省。而且纠正结果只停留在那一轮会话里，卡片本身仍然是旧的，下一个会话还要再查一遍。

定期全量审查成本高，也跟不上每天新增的卡片。更省力的做法是在使用时修卡：Agent 召回一张卡并对照当前代码核验时，如果发现不符，就当场把卡改对。这样真正被用到的卡会在使用中保持新鲜。

## What Changes

- 会话开始时注入的召回引导新增一条要求：核验召回的卡时发现它与当前代码或环境不符，就在同一轮内修订该卡。修订用 `memex_write` 完成，保留原标题和创建日期；首段改为当前事实；正文末尾追加一条带日期的修订说明，写明改了什么、依据哪个文件和行号。结论已完全不适用时，在卡内说明，不删除卡片。只修订本轮实际核对过的事实。
- 环境级 Agent 指令（`instructions/dsh-home.md`）的写卡说明补充同样含义的中文，与注入文本保持一致。
- 不新增工具，不改写入逻辑，不改检索，不自动检测或修改卡片。修订仍由模型显式调用写入工具完成。

## Impact

- 代码：`packages/dsh-memex/src/lifecycle/index.ts` 中注入的召回引导文本。
- 指令：`instructions/dsh-home.md` 的写卡说明，经 sync 物化到 `$DSH_HOME/AGENTS.md`。
- 测试：`packages/dsh-memex/test/lifecycle-runtime.test.ts` 的注入文本断言。
- 版本与部署：dsh-memex 0.4.0 → 0.4.1，`dsh.yaml` 同步版本；需 `dsh build` 并重启 DSH，在用户确认 DSH 空闲后进行。
- 行为副作用：修卡会被记为“本会话已写卡”，因此该会话的回合结束写卡提醒不再出现（见 design.md）。
- 评估（仓库外，不提交）：用写卡遥测中 `overwritten` 事件和修订说明统计“使用时修卡”的频率；按月随机抽样检查过期比例是否下降。
