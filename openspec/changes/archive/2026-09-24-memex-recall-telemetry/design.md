# 设计：召回遥测

## 1. 要解决的问题，以及它的固有难度

两类失效：

| | 可观测性 |
|---|---|
| 应召回而未召回（false negative） | **本质上不可自动判定** |
| 召回了但无有效信息 | 可部分自动判定 |

第一类不可自动判定的原因是循环依赖：判断「本该召回什么」需要知道正确答案，而那正是发起
检索的原因。实测证据——同一张 `dsh-session-archive-attached-guard`：

```
会话 归档 占用 → 命中      删不掉   → 0 条
attached       → 命中      占用中   → 0 条
删除失败       → 命中      无法删除 → 0 条
```

三次 false negative 的返回形态，与域外查询（`怎么养猫 猫粮推荐` → 0 条）**完全一致**。

因此本变更**不试图自动判定 false negative**，只做一件事：把判定所需的事实记下来，让人在
事后（尤其是写 retro 卡、已经知道答案的那一刻）能够回填。

## 2. 为什么现在做：分段修复改变了失效形态

`memex-cjk-query-segmentation` 在同一批 gold set 上的效果：

| | 修复前 | 修复后 |
|---|---|---|
| 命中正确卡 | 15 | 26 |
| 返回了但没有正确卡 | 6 | **8** |
| 返回空 | **13** | **0** |

空结果归零是好事，但它同时**消灭了最显性的失败信号**。修复前「搜不到」会以空结果暴露；
修复后同样的失效表现为「返回了 4 条但都不对」，使用者会以为搜到了。

这不是反对那次修复——它的净收益明确。但它把剩余失效推向更隐蔽的形态，因此可观测性
从「可选」变成了「必要配套」。

## 3. 记什么：判据，不是原文

**不记查询原文和卡片正文**，两个理由：

- **隐私**：查询与卡片都可能含敏感信息。一个观测设施不应成为新的数据留存面。
- **不需要**：要回答的三个问题都不需要原文。

| 要回答的问题 | 所需字段 |
|---|---|
| 哪些卡是死重量 | 返回的 slug 集合 |
| false negative 有多频繁 | 返回条数是否为 0 |
| 是否靠正文噪声凑数 | 每条命中是否来自高权重字段 |

查询侧只记**形态特征**：token 数、是否含汉字、是否经过分段。这足以分辨「中文自然语言提问」
与「代码 token 精确查找」两类场景的表现差异，而不泄露问了什么。

## 4. 「高权重命中」如何判定

依据内核的打分机制（已读源码确认）：

```
FIELD_WEIGHTS = { slug:5, title:5, tags:4, category:3, headings:3, wikilinks:2, body:1 }
```

且 `meetsThreshold` 的**高信号豁免**只认 `slug`/`title`/`tags`：一个词命中这三者之一
（且非停用词、非 31 个泛词）即可让整张卡免于覆盖率门槛。因此「命中是否落在 slug/title」
是一个有实际排序意义的区分，而不是任意选的指标。

⚠ **一个被实测否决的方案**：最初打算复用内核输出里的 `> 匹配行:` / `> Matched:` 行，
以为前者代表正文命中。读 `formatter.ts` 与 `findMatchLine()` 后确认这是错的：

- `匹配行` = 该词**在正文里出现过**（与它是否同时命中 slug/title 无关）
- `Matched:` = 该词**只在元数据**，正文完全没有

实例：`dsh-proxy-model-differs-by-seam` 的 slug 含 `proxy`（高权重命中），但因为正文里
`proxy` 也出现了 7 次，输出显示的是 `匹配行` 而非 `Matched:`。**内核输出无法区分高低权重命中。**

**实际采用的判据**：在调用方自行计算——查询 token 是否出现在该条命中的 `slug` 或 `title` 中
（ASCII 按分隔符切段后整段比较，汉字按子串）。这两个字段本来就在检索返回里，无需内核配合、
无需改动调用契约。实测可正确区分：`proxy`/`hardlink`/`会话 归档` 判为有锚点，
噪声 bigram `不能` 判为无锚点。

这是一个**近似**而非内核判定的复刻（不含 tags/category、不复刻停用词与泛词表），因此它
只用于统计趋势，不用于改变任何检索行为。

## 5. 放在哪：库外，插件自有目录

现行 `dsh-memex-memory` spec 明确禁止在库中引入私有 frontmatter、私有存储格式或私有索引，
并要求库可脱离本系统被内核 CLI 与 Obsidian 独立使用。遥测若落在库内会同时违反这两条，
还会污染卡片同步（库是 git 仓库）。

因此落在 `$DSH_HOME/plugins/dsh-memex/`，与 `dsh-pet` 的 `$DSH_HOME/plugins/dsh-pet`
同一惯例。格式用 **NDJSON 追加**：一行一条，崩溃只会损坏最后一行，读取方逐行解析、跳过坏行，
无需锁也无需读改写。

## 6. 可靠性边界：旁路，失败即放弃

遥测服务于度量而非功能。让记账失败导致检索失败，会把观测设施变成新故障源。因此所有写入
路径吞掉异常，最多经 logger 提示一次（不刷屏），检索结果逐字节不受影响。

这条在 spec 里写成可验证条件（「对同一库同一查询，遥测可用与不可用时返回完全相同」），
以免日后有人「顺手」把它改成 fail-closed。

## 7. 与「按工作区关闭记忆」的关系

`memory: false` 的工作区，其会话完全不触达记忆层。若仍留遥测，等于在一个被明确关闭的边界上
留下该工作区的活动痕迹。判定必须在现有的 `currentFor()` 拒绝路径**之后**——那里已经
先于 `ensure()` 拒绝，因此天然不会产生记录，只需确保不在更早的位置插入记账。

## 8. 不做的事

- **不自动判定「这次召回有没有用」**。是否有用取决于人有没有据此改变做法，这个信号不在
  检索侧。记录只提供「被召回过」，「被用过」需要另外的显式动作。
- **不引入评分或模型**。与 `不引入向量检索` 一致，默认路径零网络外发。
- **不做 UI**。先积累事实，够用的分析用一次性脚本即可；过早做界面会固化尚未验证的指标。
