## Why

B035 的真实 Q&A 子会话 fork 了主会话的 77 轮历史，继续扮演 GUI 中的主 agent，turn 正常结束却未发送飞书回复。所有者已确认：Locus agent 应拥有独立上下文，需要时发现并询问同源协作者，而不是克隆父历史或自动共享认知。

## What Changes

- 新增**同源协作上下文**：主会话及其有效 Locus children 共用的一层逻辑能力，包含公共工作事实、协作者发现和定向询问；不是文件夹，不复用已闲置的 Skill store，也不新建文档内容仓库。
- 公共工作事实按主会话只维护一份：项目说明、资料引用及已确认共同约束，由所有者明确确认其同圈共享范围后版本化保存，agent 按需读取最新版本；挂载不复制 N 份、更新不自动广播、不从父历史或问答结果自动提取/采纳。引用不授予资源读取或写入权限。
- 首个挂载幂等启用空公共记录，未确认内容标未知；后续成员引用同一记录。最后一个 child 退出不删除公共事实，主会话可查询已建立的公共上下文，成员列表为空；主会话失效则拒绝 agent 访问并保留 owner 历史。各 Locus 局部锚点、执行根核验、权限与回复关联保持独立，既有局部内容不自动提升为公共内容。
- **BREAKING（仅新建及显式重建的 Locus child）**：不再复制父会话 transcript，也不默认注入父摘要；只初始化身份、服务入口、可信工作归属、权限与协作能力说明。自身历史持续保留，冷恢复不重新播种。已有 fork child 保留历史和原上下文模式，不能被静默改造。
- 引入 caller-bound 协作者名单：主会话发现自己的有效 Locus children；child 发现自己的主会话及同源有效 Locus children。名单按持久索引派生，不扩展到整个 workspace、普通临时 subagent、其他父子树或跨 Host。
- 父子首次关联、已加载动态装配、冷恢复和原生 GUI 加载均可取得 scoped 协作工具及简短说明；名单更新不唤醒模型、不广播成员历史。
- 支持父子及兄弟之间定向异步询问；目标忙时排队，不 steer 当前任务。Host 关联请求、答复与原始工作，答案到达后由询问方继续，不经父模型中转。询问不设业务时间期限，长期等待继续占用有界队列并可由实际 caller 显式取消；取消仅记录持久状态与结构化日志，不产生飞书消息、表情或 Delivery。
- 圈内询问无需逐次人工审批，但仅分享适合请求用途和最终受众的工作上下文，不开放完整历史；询问不构成提权、能力转授或任意跨群披露授权。被问方保留自身正常业务工具与既有权限上限，可为形成答案执行其本来获准的必要操作；询问轮硬禁飞书代发、普通跨 agent 消息、再次委派及权限/绑定变更。
- 飞书请求跨询问轮次保留精确 Delivery 关联；普通 agent 消息、GUI 输入与询问答复不得串用回复权。turn 结束、询问已投递和业务正文已发送是不同事实；无回复或回复结果未知时如实诊断，不自动代发正文或重放工作。
- 管理面标识旧 fork / 新独立上下文模式，所有者可在无在途工作时显式重建：同一入口、新 child、新代际、默认 read，旧历史保留。

## Capabilities

### New Capabilities

- `pet-collaboration-context`：同源公共事实的单一归属、范围内自主更新与版本化留痕、caller-bound 按需读取、挂载/退出生命周期及局部上下文边界。
- `pet-agent-inquiries`：同源协作者名单、scoped 发现、定向异步问答、请求关联、忙时排队、恢复、防循环及内容与权限边界。

### Modified Capabilities

- `pet-locus-collaboration`：独立上下文替代新 child 的父前缀继承；agent 名单与 owner 发现分离；Delivery 跨询问轮次关联与存量显式重建。
- `dsh-pet`：明确新上下文模式对既有继承条文的替代范围，补充主/子会话协作工具的 scoped 生命周期，保持普通轮盘 Invocation/Snapshot 与 Skill 边界。

## Impact

- Pet Host：`src/host/locus/` 的 child/context/仓储/管理/turn-observer、工具与加载装配；新增受限询问服务、持久询问记录和执行关联。Web 仅增加按主会话编辑/确认公共事实的最小 owner 入口，以及模式、询问诊断与显式重建所需信息，不承接 B026/B030 的完整管理面重设计。
- DSH：优先验证已安装 spawn provider 的零父历史能力；原生 `list_agents` 只列自身子孙，`send_message` 只支持直接父子且可能 steer，均不能冒充本需求。所需 Host 接缝先做可失败核验；若需 compatibility patch，沿用已审查、精确 pin 的 Pet Host runtime 流程，不扩大全局工具语义。
- 数据与安全：名单关系复用 locus 正反向索引；同源公共事实、修订来源及询问状态与投递关联复用 Pet 持久化体系，不新增文件目录或成员关系真相。已有未知执行结果不自动重放；新结构版本变化按现有离线备份/迁移规则，不自动迁移旧 child 历史、不读取凭据。
- **前置 change**：`pet-unified-locus-collaboration` 已有实现但未归档；本 change 的 delta 基于其拟发布规范（尤其同名 capability），不是基于已替代的 `pet-locus-multi-binding`。实施前确认基线，规范合并/归档必须先完成前置，再应用本 delta；前置若变化，先重对齐，不将本 delta 当作新 ADDED 全量能力或倒序覆盖。
- **相邻 backlog**：B027 负责通用安全失败回执，本 change 定义未回复/询问失败的事实和诊断接缝，不扩展 Host 代发业务正文；B028 的显式模型切换/降级不在本期，新独立 child 须显式保留经核验的创建模型策略，不能因换 provider 静默换模型。

规划只授权文档生成，不授权实现、部署、建群、迁移、重建或修改现有 session。
