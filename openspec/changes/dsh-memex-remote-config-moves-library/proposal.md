## Why

「记忆」设置页能改一个库的目录（`scopes[].home`），也能配置/更换它的远端，但两件事是**分开**的，于是
一个库一旦配了远端，就再也没法把目录换到别处：

- 库的 `.git` 与 `.sync.json` 活在**目录里面**；只改配置里的路径，远端绑定留在旧目录，新目录是空的。
- 内核的 `sync --init` 只做 init + push，**从不 clone**；对空的已配置目录再 init，等于把第二条历史推给
  同一个远端。
- 规格里「已配置的库绝不会被重新初始化或重建」是对的，但它同时意味着没有「搬到新目录」这条路径。

2026-11-04 的现场：`prgrmrwy-home-substore` 曾被整目录复制进 `personal` 的卡片，需要清理；同时用户提出
更根本的诉求——**设置新远端时应当能顺便替换原来的目录**，而不是只能「先删库再重建」。

## What Changes

- **远端配置动作可以同时迁移库目录**：远端区块新增一个可选的目录输入（占位符是当前库路径，留空表示
  不动）。填了新路径时，确认动作按「先搬家、再落配置、最后退休旧目录」执行：
  1. 宿主把旧库的卡片复制进新目录（同名 slug **保留目标目录的副本**，与切换主入口的合并规则一致），
     并把 `.git` / `.sync.json` / `.gitignore` 一并带过去——但只在目标目录没有自己的那一份时；
  2. 宿主在**新目录**里执行内核动作：给了新远端就跑 `sync --init <url>`，没给就跑 `sync`（沿用现有远端）；
  3. 页面把 `scopes[].home` 持久化为新目录；
  4. 配置确认指向新目录后，页面再让宿主删除旧目录。
- **删除只发生在可证明的情况下**：宿主只删除「本次自己搬过、且配置已解析到目标目录」的旧路径，并拒绝
  删除文件系统根、home 目录，以及仍包含其它在用库的路径。
- **失败保持原状**：任一步失败都不会动旧目录；搬家幂等，重试只补缺的部分。配置未被接受时旧目录照样保留
  （页面提示）。
- **不改的东西**：不改卡片格式、不动远端仓库内容（远端仍是内核在管）、不改变发布方向与守门、不新增设置项
  之外的持久字段。

## Capabilities

### New Capabilities
（无）

### Modified Capabilities
- `dsh-memex-settings-ui`：「远端写入按状态分流，且从不重建库」新增一条——配置远端时可同时把库目录迁到
  新路径，并规定顺序、合并规则、删除前置条件与失败语义。

## Impact

- `packages/dsh-memex/src/scope/library-move.ts`（新增：目标校验、库目录搬迁、可删除性校验）、

- 不影响：现有「已配置的库不出现初始化动作」的约束（迁移是显式的新动作，不是重建）。
