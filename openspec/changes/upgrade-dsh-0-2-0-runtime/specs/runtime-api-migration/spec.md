## ADDED Requirements

### Requirement: 被移除的事件、消息来源与设置接口必须按语义等价迁移

当目标运行体移除了 local package 依赖的生命周期事件、消息来源类型、设置承载接口，或改变了消息中工具结果的表示方式时，迁移必须（SHALL）先查清目标运行体中的承接机制，再按**原有语义**适配。适配必须保持触发时机、写入格式可被目标运行体完整读回、配置分层与校验语义不变。

对会写入持久化 Session 的改动，系统必须（SHALL）用目标运行体的持久化读取路径证明：写入的内容可以被重新加载。仅凭编译通过不得（SHALL NOT）视为满足要求，因为目标运行体可能在读取时才拒绝不合法的内容。

在类型层面不报错、但在运行时改变数据形态的变更（例如工具结果从消息内容块改为独立消息），必须（SHALL）由覆盖新形态的测试证明适配正确。

#### Scenario: 会话开始事件被移除
- **WHEN** 某 local package 订阅的会话开始事件在目标运行体中已不存在
- **THEN** 该订阅 SHALL 改为目标运行体中触发时机等价的事件，并证明注入或绑定仍在首个回合之前完成

#### Scenario: 插件写入的消息来源类型被移除
- **WHEN** 某 local package 以目标运行体已不支持的消息来源类型写入会话
- **THEN** 该写入 SHALL 改为目标运行体允许的插件自有来源类型，并证明含该消息的会话可被目标运行体完整重新加载

#### Scenario: 工具结果改为独立消息
- **WHEN** 目标运行体把工具结果从消息内容块改为独立的工具消息
- **THEN** 依赖工具结果配对的 local package SHALL 按新形态识别调用与结果的对应关系，并以覆盖新形态的测试证明不会把已有结果的调用误判为孤儿

#### Scenario: 设置承载接口被移除
- **WHEN** 某 local package 使用的设置注册与绑定接口在目标运行体中已删除
- **THEN** 该 package SHALL 迁移到目标运行体的插件配置机制，保留缺省值、校验失败拒绝与 last-good 语义，并把用户已有配置迁移到新承载位置而不丢失
