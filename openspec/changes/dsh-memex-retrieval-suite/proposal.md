## Why

dsh-memex 的「找得到」这一段目前没有可回归的度量。现有固定自检的虚构库只有 2 张卡，测不出排序；2026-09-23 那套 34 题 gold set 没有入库，已不可恢复；2026-10-30 的探针只有 12 题能打分，任何检索改动的效果都会被样本噪声盖过。用户已决定继续优化 memex（决策记录在仓库外评估目录），后续改写卡约定、补 tags、链接扩展或混合检索，都需要先有一条用自己数据测出的基线。

同一次探针还暴露了两处会污染评测的问题：评测与交接类卡片引用查询原文，会把目标卡挤出前十；固定自检的召回层只看事实是否到达，不记录目标卡是否被返回、排第几，fail 拆不开「没找到」和「找到没用」。

规范与实现之间还有一处已存在的偏差。现行 `dsh-memex-memory`「不引入向量检索」要求底层调用不携带语义开关，但插件的 `memex_search` 已向模型暴露 `semantic` 参数，并原样传 `--semantic` 给内核（`src/tools/index.ts:318-323`），没有任何来源检查。内核在库未显式配置向量来源时，会按环境自动选择 OpenAI 或 Azure，并把未缓存卡片的全文送去向量化。也就是说，今天只要模型传了 `semantic: true`、进程环境里又有对应的 key，整库卡片就可能外发。

该要求在 `archive/2026-09-20-dsh-memex-scoped-memory` 的 design「不做」清单中以「默认关键词路径零外发」的形式出现，同一次归档的 delta 把它写成了正式禁令；现有规划材料没有记录禁令之外的论证。本 change 重新选择约束的对象：检索用什么表示方式是手段，要守的是卡片内容不越出库的访问权限边界（同一期设计 D3「库的划分依据是发布目标与访问权限」）、成本可见、默认路径的更换有评测依据。本机实测上游语义检索在 12 题上明显差于关键词（MRR 0.31 对 0.63），说明「加向量」必须先过评测。

## What Changes

- 新增 CLI `dsh-memex-eval-retrieval`：对一份安全制作并冻结的卡库快照运行一套 gold set。零 LLM，不写召回遥测，只用关键词后端；后端走与插件 `memex_search` 相同的参数构造和内核调用。
- 快照分两个阶段：
  - 制作阶段只读原库，只接受普通的独立文件；
  - 写入域（快照、报告、冻结观测）固定在 `~/.dsh-memex-eval/retrieval/` 下，创建前逐级检查祖先，不得落在任何记忆库之内；
  - 按规则排除评测与交接类元卡；可以加入新 slug 的人造干扰卡。
- gold set：可接受目标卡是 OR 集合；题型只作标签。整个文件先做全量校验，再按显式选定的集合运行。
- 报告：
  - 指标包括首位、前三、前十命中率，MRR，空结果率，误选率；
  - 成本列在同一张表里（端到端耗时、按 `chars-v1` 计的返回字符数、安装与快照大小），不设门禁；
  - 逐题观测和成本观测都冻结，删掉快照也能离线重算；
  - 出错的题保留在分母里，这一轮标为 incomplete。
- 固定自检加一项诊断：从已冻结的工具返回全文中解析目标卡是否被返回、最好排第几。空召回记「未召回」，证据不足记 unknown，无记忆条件记 N/A。不改判定，不改夹具，旧轮次也能离线补算。
- **BREAKING（插件行为）**：插件 `memex_search` 收到 `semantic: true` 时，在参数层整体拒绝，所有目标库都不调用内核。工具参数和描述保持内核原文。这样堵住了今天就存在的外发路径。
- **BREAKING（规范层）**：`dsh-memex-memory` 移除「不引入向量检索」，代之以「检索后端的来源边界与更换条件」：
  - 默认且唯一启用的是关键词路径；
  - 卡片内容不得越出库的访问权限边界；
  - 今后启用任何向量来源都须另开 change，定义来源判定、配置一致性、模型获取不携带卡片内容，并附评测证据；
  - 写明威胁模型：防范误配置和环境里残留的凭据，不防范能改动本机文件的人；
  - 成本随评测报告呈现，不设门禁。

  相应修改 `scope` 参数要求里「不传 scope 时与内核原生一致」的例外，以及 integration 分段要求里的语义场景。
- 插件会话开始时注入的 memex 引导新增一句：评测、探针、交接类卡片不要粘贴评测查询原文，改用题号或 gold set 文件路径（与 `instructions/dsh-home.md` 已有约定一致）。

明确不做（留给后续 change）：
- 本地语义与 RRF 混合后端，以及向量来源的启用；
- 检索时沿 wikilink 扩展一跳邻居；
- 修改内核；
- 无 query 的 recall、多库归并的 parity。

gold set 的扩题和封存集写作是人工工作，也不在本 change 内。

### New Capabilities

（无）

### Modified Capabilities

- `dsh-memex-evaluation`：新增检索层离线评测（文件系统边界、不可变输入清单、gold set 契约与选集、与插件一致的关键词检索、冻结观测与重算、指标与成本同表）；固定自检新增目标卡召回名次诊断。
- `dsh-memex-memory`：移除「不引入向量检索」，新增「检索后端的来源边界与更换条件」（插件语义请求整体拒绝）；修改 `scope` 参数要求，声明语义拒绝是原生一致性的唯一例外。
- `dsh-memex-integration`：会话开始注入的引导新增「评测类卡片不贴查询原文」的提示；分段要求中的语义场景改为「当前被拒绝」。
