# 统一 locus 协作架构

## Context

本文从产品模型定义完整目标系统，不是旧设计的补丁。动机见 proposal；旧草案 `pet-locus-multi-binding` 不参与本设计的约束推导。接受旧关联不可用，不编写旧关联迁移器。

Pet 运行于 DSH Host 内，Web 是管理入口。DSH 提供持久 session、运行实例、continuable 子会话、队列与沙箱；飞书提供群、话题、成员和消息；lark-cli 管理 bot 身份与凭据。本仓不是 DSH core，不能把尚不存在的宿主能力假定为已实现。

当前可复用接缝：`qa/subagents.ts` 的 live parent、startContinuable、queuePrompt、resume 与结算观察；`qa/action.ts` 已共享 GUI/绑定的 fork 过程。现有 channel/route 的 QA/workspace 分支是本期被替代的实现，不是新领域模型。不改普通 Pet 轮盘的 root executor/Invocation/Snapshot。

证据边界：topic 群消息读取验证过稳定 thread ID，但独立 consumer 未抓到原始入站事件；sandbox roots 的契约检查不是实测写入；fork 接口未发现 cwd override 不等于证明所有宿主扩展都不可能。相关接缝必须在实现初期做可失败的能力验证，不能复用旧稿“全部 spike 通过”的结论。

## Goals / Non-Goals

**Goals**
- 一句话解释所有场景：确定主会话，为飞书入口建立 locus，由专属子会话持续服务。
- 研发先行与项目群先行只是初始化来源不同；运行链完全一致。
- 群/话题层级补齐且幂等，执行树最多两层；双向可发现。
- 只有明确触发才做业务工作；默认 read，授权是独立控制动作。
- 文档同时覆盖正常流程、历史、并发、故障和宿主边界。

**Non-Goals**
- 不兼容旧关联、不迁移飞书 Invocation，不保留两套飞书执行机器。
- 不替换普通轮盘技能体系，不全局删除其它 snapshot 使用的 worktree adapter。
- 不建设群级 workspace 覆盖、自动项目知识汇总、跨子会话记忆同步、工作目录复制或写冲突锁。
- 不自动删除旧 session/历史/群；不把文件 read/write 扩大解释成所有 API 的权限控制。

## 1. 核心理念

### 1.1 工作现场与协作现场相连

工作现场 = 主会话中的研发上下文 + workspace 归属 + 经确认的实际工作目录。
协作现场 = 飞书群本体、话题或单聊入口。Locus 是两者的持续关联，子会话是执行载体。

```text
Workspace W
   |
主会话 S（研发已有，或 project 群自动创建）
   +-- 子会话 C0 <-- locus L0 --> project 群 G
   +-- 子会话 C1 <-- locus L1 --> G / 技术话题 T1
   +-- 子会话 C2 <-- locus L2 --> issue 群 H

主会话 S2
   +-- 子会话 C3 <-- locus L3 --> G / 显式绑定话题 T2
```

Source 不必先于飞书存在：自动主会话给协作先行提供工作根。自动不是另一种执行者类型，只是主会话的建立来源。

### 1.2 一套领域名词

| 概念 | 职责 | 身份与边界 |
|---|---|---|
| 主会话 | 共同工作基础、workspace/工作根、子会话收纳 | 持久 DSH session；不必始终运行，也不处理每条群消息 |
| 子会话 | 专属于一个 locus 的持续工作对话 | 持久 session；subagent 是创建/运行它的技术机制，不是另一个业务对象 |
| Locus | 关联飞书入口与主/子会话，承载权限与生命周期 | 一代关联有 locusId；endpoint 定位当前代 |
| Endpoint | 飞书寻址 | `(chatId, threadId?)`，群与单聊均用 chatId；messageId 属于投递，不属于一般入口键 |
| Workspace | 工作区归属 | 从主会话推导，不能任意和另一个主会话组合；不等于实际 sw 工作根 |
| Delivery | 一条被接受的消息与一次子会话执行之间的关联 | 去重、排队、结算、回复目标；不是持久业务任务 |

Task 如仍供 Pet 公共管理面使用，仅是 locus 生命周期的内部投影；不新增“locus → binding → agent → child session”四层业务对象。Invocation 不存在于新飞书执行链。

## 2. 系统结构与责任

```text
GUI Q&A / 管理                        飞书事件（消息 / bot 入群）
       |                                         |
       |                                  身份、mention、防重放
       +----------------------+------------------+
                              v
                      Locus Controller
       [ensure group / resolve parent / ensure locus / switch / scope]
                  |                      |
                  v                      v
          Locus Repository          DSH Session Adapter
          正反向索引/代际          主会话创建/恢复、子会话/inbox
                  |                      |
                  +------- Context / Policy -------+
                                         |
                                   子会话执行
                                         |
                            Delivery 关联 / 结算观察
                                 |              |
                           Host 表情        子会话文字回复
                                 +------ 飞书 --+
```

- 接入层只解释平台事实，不猜 parent，不以模型输出判定身份。
- Controller 决定创建、切换和授权；普通工作内容交给子会话。
- Repository 保存一份真相及其索引；Web 正反向视图均由它投影。
- DSH adapter 管持久 session 与当前运行实例的区别：卸载不解除 locus，恢复不换子会话。
- Context 服务按实际 caller 返回 locus；Policy adapter 核验实际文件策略。
- 子会话负责业务回复，Host 仅发机械控制回执和表情，避免重复代发。

## 3. Locus 聚合与索引

建议逻辑记录（字段是设计草图，非直接代码 schema）：

```text
locusId / generation
endpoint: { chatId, threadId? }
parentLocusId?                     话题所属群级结构，仅结构关系
workspaceId / parentSessionId / childSessionId?
source: auto | inherited | explicit | qa-created
state: provisioning | active | switching | invalid | retired
permission: desired / effective / verifiedAt / grantedBy
contextAnchor: executionRoot? / constraints / provenance / confirmedAt
createdAt / retiredAt / replacesLocusId?
```

子会话在 provisioning 阶段可尚未创建，active 必须完整。话题结构指向群级入口，历史上群改绑不改写话题的 parentSessionId。

索引：
- `endpoint -> current locus`：最多一个当前服务代际；去重与投递入口。
- `parentSessionId -> loci[]`：可按状态过滤，发现全部关联。
- `childSessionId -> locusId`：执行反查，不能一子多 locus。
- `parentSessionId -> defaultQaLocusId`：GUI 默认入口，与其它绑定列表分开。

不把 workspace/parent/child 全拼入 endpoint key：入站时未知这些值，且改绑会失去冲突检测。历史按 locusId 保留；正反向索引同事务维护，不存两份独立绑定真相。

## 4. 层级补齐与主会话解析

### 4.1 统一流程

```text
resolveEndpoint -> lookupActiveLocus
                         | hit -> 使用固定子会话
                         | miss
                         v
                   ensureGroupContext
                         v
                    resolveParent
                         v
                     ensureLocus
                         v
               prepareChild(read) -> publishActive
```

`ensure` 表示幂等，不表示每条消息重新创建或重新继承。群锁负责群结构创建，入口锁负责 locus；锁顺序固定为群→入口，数据库条件提交防止并发赢家覆盖。

### 4.2 四种入口

| 入口 | 群级结构 | 主会话选择 | 结果 |
|---|---|---|---|
| GUI Q&A | 无默认入口才创建新群，指定本人群主 | 当前研发主会话 | 新 locus/子会话；以后打开默认群 |
| 群 bind | 当前群结构不存在则直接以指定来源建立 | 显式前缀解析的主会话 | 不必先创建一个马上丢弃的自动主会话 |
| project 群自动建立 | 在 default workspace 建一个群专属自动主会话 | 每群一个，不按 workspace 全局共享 | 群级 locus；子会话业务执行按需启动 |
| 话题首次触发 | 先 ensure 群；缺失时先建群自动主会话 | 显式指定优先，否则取群当前主会话 | 在取得的主会话下建立兄弟子会话 |

已有入口永远先命中，不因 default workspace 或群来源变化改变 parent。群明确失效不是缺失，必须诊断，不静默换 default。

### 4.3 创建顺序稳定

`ensureGroup(G); ensureTopic(G,T)` 与 `ensureTopic(G,T)` 得到同样的群主会话归属。
两个话题并发首次进入，只创建一个群自动主会话。显式 topic S2 不把 S2 上提为全群默认。
不存在 `群子会话 -> 话题子会话` 的 fork；主会话唯一来源树深度两层。

### 4.4 Bot 入群与首次 at

入群是关联初始化事件，不读取/分析全部历史，不回复业务内容。启用 channel 和已验证授权是前置；无法证明邀请人/初始化权限时，不扩大群准入，记录待建立状态，由首次 allowlist `@bot` 补齐。平台事件缺失也由首次合格 at 幂等补齐。
主会话先持久初始化 workspace、群标识和基础约束；若宿主 fork 要求完成轮次，首个合格 at 再执行必要初始化，不能为“只入群”偷偷跑业务推理。子会话发布 active 前完成 read 与 context 核验。

## 5. 显式绑定与上下文切换

来源规则：auto/inherited 可空闲替换；explicit/qa-created 已有显式选择，不直接覆盖（同一目标幂等确认，不重建）。忙包括已接受待处理消息；不强杀写入。

```text
自动 locus L0：S0 / C0 / read 或 write
         |
allowlist /bind S1，空闲
         v
准备 S1 下的新子会话 C1（read，context 核验）
         v
原子切换 endpoint 当前指针 L0 -> L1；L0 退役
         v
当前入口机械回执：S0 -> S1；上下文来源改变，旧历史未自动合并
```

回执以标题/短 ID 清晰区分来源，不暴露其它群信息。控制回执尚未送达时保留可重试通知并暂停新业务派发，避免无提示切换。重试回执不重建子会话。

群改绑只改变群当前 parent：已有话题固定在原 parent，新话题取新 parent。旧群 locus 退役不能级联删除仍在用 S0 的话题；自动主会话 S0 不自动归档或清理。

## 6. 统一消息交互

1. 只有明确 mention 自身 bot 的消息进入工作链（本期包括单聊）；普通消息不推理、不自动总结、不更新主会话。
2. 命令仍经过 mention、身份、消息类型、水位、去重；`-b/--bind` 与兼容 `/bind`、`-s/--scope`、`/unbind` 是控制动作。
3. 普通请求取得 active locus，记录 Delivery，再交同一子会话 inbox。接受≠执行完成。
4. 子会话按需读取有权限的群消息/文档，不把 PRD/会议/Figma 链接存在误当已吸收上下文。
5. 子会话向当前入口发问，turn 可结束。用户下一条 at 回复进入同一子会话继续；等待是对话语义，不挂着飞书 Invocation。
6. 决策答案引用问题/回复目标；有歧义时澄清，不把任意“好”当作所有者提权。GUI 工具问答不自动桥接成飞书问答。
7. Host 关联对应执行结算更新表情，文字由子会话发送。初始化/GUI 私聊/父子补问不产生飞书 Delivery。

Delivery 至少关联 endpoint、locusId/代际、child、messageId、sender、dispatch/turn 关联、状态。仅 child ID + 最老 pending 无法排除私聊/初始化交错；适配器必须证明执行对应关系，不能证明时不打错表情。恢复未知执行结果不盲目重放副作用。

## 7. 上下文与代码工作空间

三层上下文：
- 主会话继承前缀：fork 时可用的已完成内容，不保证含最新目录，也不持续同步。
- locus 锚点：project 群/资料入口、workspace、实际执行根、工作约束、来源与确认状态。
- 请求上下文：当前消息/话题、发送者、回复目标，只属于本次 Delivery。

`pet_context()` 从 caller child 反查 locus，不接受任意 target ID；普通轮盘 caller 仍返回当前 Invocation/Snapshot。权限和锚点查询在恢复后仍可用，普通会话看不到此工具。

子会话首轮任务书允许按需问主会话当前工作目录。信息经确认后持久化，后续只需查询锚点，不重复完整 prompt。路径存在性与来源授权分开；普通目录/ws/sw 都可成立，不要求必须是 git worktree，不自动另建 sw。

主会话不是群子会话历史的实时副本：新话题默认继承主会话和项目入口，需按需读飞书资料。兄弟会话无自动记忆同步。用户可让主会话主动查看子会话；不新增自动总结回报链路。宿主原生父结算通知须单独检查和抑制，不能用 prompt 冒充已做到完全静默。

### 7.1 现场关联与上下文协同是两层能力

**当前模型解决关联，未来模型解决知识如何流动。**

关联回答“哪些工作现场与协作现场相连、由谁持续跟进”；知识流动回答“哪些事实、发现与决策应当被谁分享、吸收和采纳”。前者为后者提供可发现、可追溯的基础，但不等于已经实现后者，也不要求两者在本期同时交付。

本期解决工作现场与协作现场如何关联、谁持续跟进、如何查找到相关工作。**主会话目前提供初始上下文和工作归属，不自动维护项目全局最新认知。** 父子关系是本地执行组织；统合是可选择的职责，不是父节点的天然能力或特权。

| 层 | 问题 | 本期边界 |
|---|---|---|
| 现场关联 | 工作在哪里发生，由哪个子会话负责？ | 完整实现 locus、层级补齐、持续交互和双向发现 |
| 上下文协同 | 哪些发现应被谁吸收，成为何种知识？ | 用户按需发起，不建设自动汇总、冲突裁决与知识同步系统 |

例如 QA 子会话发现一个问题，不意味着主会话已经知道；评审中有人提出建议，不意味着项目已采纳。**收到信息不等于采纳信息，对话里出现过不等于已确认决策。** 不以自动回传摘要掩盖这些差别。

### 7.2 本期的轻量协同入口

```text
用户：查看 QA 现场最近发现的问题，对当前方案有什么影响？
    -> 通过双向索引找到相关 locus / 子会话
    -> 在权限与宿主读取能力允许时查阅相关历史
    -> 带着来源整理，回到当前工作现场讨论是否采纳
```

这里是用户主动发起的按需查阅与推理，不要求每条飞书消息都经过主会话，也不要求子会话结算时自动上报。本期保留关联、历史与来源引用，不预置自动采纳规则。双向索引只保证可发现，不能据此宣称任意会话历史都可读取；缺少读取能力或权限时如实说明，不声称已经汇总。

权限与上下文的方向性保持不变：可发现不授予访问，能读取不等于可以跨群披露，汇总内容不构成更改工作权限的授权。

### 7.3 后续方向记录：project 驱动的跨现场协同（不在本期实施）

未来愿景是 **Project 驱动的多方共建**：每个人都可以将自己的工作现场关联到协作现场，通过 Project 串联为分布式协作拓扑，而不只是由一位研发把自己的会话开放给其他人提问。

```text
研发 A 的工作现场 ──┐
研发 B 的工作现场 ──┼── Project 协作现场与共同知识
产品的工作现场   ──┤
QA 的工作现场    ──┘
```

各方在自己的工作现场开展工作，通过协作现场交流资料、发现与决策，并在明确分享与采纳的基础上共同建设项目知识。共同知识不是所有私人会话历史的自动合并；可选的统合角色负责整理与协调，也不因此拥有各方工作现场的全部访问或执行权限。

本期是这一愿景的起点：先做好研发个人工作现场与飞书协作现场的关联，复用上下文、持续协作；上图仅表达未来方向，不扩大本期交付范围。

这不是把所有人的主会话放进同一棵父子树。每个人保留自己的代码空间、会话、权限与判断；project 关系组织跨现场协作，统合者可以独立于某个会话父节点存在。当前 locus 不承诺已实现跨 Host 共享寻址、分布式同步或多方知识治理。

后续按真实需要逐步考虑：
1. 用户主动的查阅与汇总体验；
2. 显式分享、采纳、来源与时效追踪；
3. project 级知识统合、冲突处理和多人共建。

完整统合至少要区分事实、建议、决策、待办与风险，保留来源/时间/适用范围，处理冲突再决定是否纳入共同认知，不能等价为“每个子会话完成后给父发一段总结”。本期不预建 Project/Summary 数据模型、消息总线或空的同步接口；真正需要时以独立 change 设计。

## 8. 权限与信任模型

- 一切新 locus 默认 read，包括自动群、话题、显式绑定和替换后新代际。
- allowlist 可改变当前 locus 的共享档位；提权后该入口成员的请求都使用该档位，不是 per-sender 授权。
- 新群初始化需证明授权；授权建立的群内成员可 at 提问，控制命令始终只有 allowlist；豁免不外溢到其它 chat。
- 权限变更需操作人、时间、期望值、生效值；设置失败不能提前显示 write/read 已生效。
- Policy adapter 以真实宿主效果核验 read。新 fork 和恢复不能假定不继承父 write，也不能靠部署默认。
- write 仅在宿主能对已确认工作根提供可说明的写能力时生效；不可支持返回明确拒绝，维持 read。不隐式映射 danger-full-access；若需更宽权限必须另作明确安全决策。
- workspace-write 仍有 cwd 根限制，不能保证写入 sw 兄弟目录。执行根提示不是沙箱。
- 文件 read 不禁止外部 API 写入或上下文披露；平台 bot scopes、工具效果策略和内容边界分别适用。
- 多子会话共享代码目录，持久会话隔离不提供文件隔离；本期展示共享根风险，不发明全局写锁。

变更档位时串行化控制操作并暂停新投递。只在无在途工作时切换；忙时提示稍后，避免声称已降权但旧 shell 仍运行。恢复策略漂移时暂停服务直至重新验证。

## 9. 生命周期与一致性

```text
provisioning -> active -> switching -> active（新 locus 代际）
      |           |           |
    failed      invalid      失败保留原 active
                  |
                retired

active -- explicit unbind / archive --> retired
endpoint -- 再建立 --> 新 locusId / 新 child / read
```

旧 locus 历史不是当前占用。失效不自动重建另一身份；用户显式处理后才建立新代。
解绑/归档结束服务，不删除群或会话，保留停止标记，普通 at 不复活，所有者显式重建才清除标记。群级整体退出不影响既有有效话题，但阻止新话题自动补齐绕过退出；群来源切换则不是群级整体退出。主会话归档/无法恢复使它的 locus 失效，有限次提示。
子会话一轮完成不结束 locus，运行实例卸载不结束 session。

存储建议一个新版本 locus 域（或现有 Pet 域的新命名表），用当前入口索引 + 不变代际记录 + Delivery。source 归属、默认 Q&A 指针与替换操作同事务发布。外部群创建、DSH session 创建无法参与 SQLite 事务，使用 provisioning 记录与可恢复补偿。

| 故障/并发 | 处理 |
|---|---|
| 同 endpoint 双创建 | 单入口条件提交，一方成功，失败方回收未发布子会话 |
| 两话题首次并发 | 群级 ensure 合流为一个自动主会话 |
| Q&A 双点击 | 主会话默认入口 single-flight，不同显式群 bind 不受此锁阻挡 |
| fork 后建群失败 | 不发布 active；回收未发布资源，残留群明确提示 |
| 切换途中失败 | 发布前保留旧关联；发布后按记录恢复通知，不重复切换 |
| 重启恢复 | 核验 parent、child、context、policy 与当前代际，完成后才投递 |
| 旧结算晚到 | 只影响旧 locus 的 Delivery，不匹配新代际 |
| 表情失败 | fail-soft，仅诊断，不重复工作 |

GUI 私聊不产生飞书回复；在群/话题视图展示主/子会话与来源，在主会话视图列出全部 locus；仅所有者管理面拥有完整反向枚举，群回执不暴露其它入口。

## Decisions

1. **所有飞书执行统一为子会话**，而非用 provenance 保留两机器。主会话自动创建解决来源缺失；有成本但收敛恢复、上下文和交互。
2. **Locus 是协作聚合**，而非只把飞书地址重命名。endpoint 是其索引；binding 可作存储概念，不升为另一核心实体。
3. **创建时继承，之后固定关联**，而非每条消息动态找父。群切换不能静默改变已有话题上下文。
4. **默认 workspace 只负责自动主会话创建**，不作为另一套执行路由；未来顶层配置不影响 locus 模型。
5. **对话等待代替飞书 Invocation waiting-user**。保留原生多轮历史与消息关联，不造额外执行状态机。
6. **默认 Q&A 指针独立**，不按最近使用 issue 群跳转，避免 fan-out 改变 GUI 语义。
7. **旧模型隔离而非迁移**。无历史兼容代码，也无擅自删除历史。
8. **权限适配可拒绝，不虚报能力**。保留产品 read/write，底层不能满足即诊断，不降低安全标准来统一外观。

## 宿主适配验收门槛

这些是有失败结果的技术任务，不是搁置的产品选择：不满足即该能力不发布，不回退旧模型。

| 接缝 | 验证成功条件 | 不满足时 |
|---|---|---|
| 自动主会话 | 完成非业务初始化并可建立持续子会话；无需每条消息运行主会话 | 自动创建保持不可用并报告宿主缺口 |
| 入群事件 | 能证明 bot/群/邀请授权，重复事件幂等 | 不扩大准入；首次合格 at 补齐 |
| topic 解析 | 原始入站稳定关联 thread；不能确定时不串投群入口 | 对该消息失败关闭 |
| scope 工具 | 首轮/冷恢复/原生加载均 caller-bound，Skill 继承不被替换 | 不发布 active |
| sandbox | read 真正执行，write 的目标范围可说明，恢复策略一致 | 保持 read 或停服务；不隐式更宽授权 |
| 结算与父通知 | 正确分辨外部请求/私聊/初始化；不自动把结论注入父会话 | 停在适配任务，报告需要宿主支持 |

## Risks / Trade-offs

- 自动主会话增加 session 数量 → 每群幂等复用，初始化轻量，历史收纳可见。
- 群主会话切换后新旧话题使用不同来源 → 显式切换警告、双向视图展示，不冒称全项目已同步。
- 项目知识并非自动汇总 → 群为可读原始资料，只有 at 触发按需检索；后续知识维护单独设计。
- 共享工作根发生写冲突 → 展示风险；不以多个 child 宣称资源隔离。
- 宿主适配未验证 → 以真实样本、失败注入、读写矩阵验收；不以类型检查代替运行效果。

## Migration Plan

这里是破坏性版本切换，不是数据模型转换。

1. 停止旧 channel 消费并处理/标识在途工作，备份一致数据库；不升级过程中继续旧 child 投递。
2. 初始化独立的新 locus 版本与表；旧 QA/chat route/飞书 Invocation 不自动转为新 locus，不作为新索引 fallback。
3. 普通 Pet Task/Invocation、源 session 与历史保留。管理面说明旧关联不可用，需重新建立；旧群仍存在。
4. 若消息入口命中仍可识别的旧关联，在所有者确认重建前不悄悄以 default 新身份接管，给出重建提示；这只是版本退役保护，不提供旧执行兼容。
5. 新建关联从 read 开始，走统一验收。回滚停新消费后恢复匹配旧程序的备份，不将新多位点数据有损降维。
6. 旧草案标记被本 change 替代，不作完成归档；实际删除/清理另需授权。

## 架构验收场景

A. 研发 session Q&A 创建/复用，随后绑定多个 issue 群，全部是同父的独立子会话。
B. project 群先行默认 workspace 自动主会话，只有 at 工作，资料消息不推理。
C. 话题先行/群先行/双话题并发得到同一个群主会话；显式话题 S2 不污染群默认。
D. 自动 S0 改绑 S1，当前群收到明确上下文变更提示；旧话题 S0、新话题 S1，权限新代 read。
E. 子会话向飞书问决策并结束 turn，下一条 at 正确继续；没有飞书 Invocation。
F. 双向发现、失效/退役/重建、冷恢复、权限失败、晚到结算与 GUI 私聊不串出站。
