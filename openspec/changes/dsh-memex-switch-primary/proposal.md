## Why

「记忆」设置页目前**无法可靠地切换一个工作区的主入口**，而且主入口在页面上不总是可辨认的。实测（2026-09-25，
用户截图）：

- ohmydsh / dsh-cockpit 两块各只有一行 `personal`，**既没标「主」也没标「附」**。原因是规范要求「只有一行时
  无需标注」，而主入口就是 `personal` 时兜底行又被隐藏，于是整块没有任何角色信息，读者无法判断这行是什么。
- 「设为主入口」只出现在**已声明的附加入口**展开态里：兜底行（`personal`）、派生主入口都没有这个动作；
  只有一个入口的工作区也没有「换成别的库」的路径。
- 就算能切，「主入口」「记忆开关」「兜底开关」三件事都写在**库的配置条目**上（`scopes[].primary / memory /
  fallback`），而一个库可以挂在多个工作区上。实测：在 ohmydsh 关闭记忆，dsh-cockpit 也一起被关（两者共用
  `personal` 条目）。切换主入口时这三个开关会跟着库走，变成「换了主入口，记忆开关自己变了」，或者在
  另一个工作区制造出两个主入口的冲突。

## What Changes

- **工作区级决定按路径声明，只能关闭**：配置新增 `workspaces[]`（`path` + 可选 `primary` / `memory: false` /
  `fallback: false`）。记忆、兜底的声明**只能写关闭**，覆盖该路径下所有目录，与会话怎样被路由无关——改认领、换主入口
  都不会让由声明关闭的地方悄悄打开；页面上的任何操作也都不会悄悄打开一个关闭的工作区（保存前逐个比较，必要时补关闭声明）。路径声明或主入口条目的旧字段**任一关闭即关闭**；旧的条目级 `primary` / `memory` /
  `fallback` **继续被读取**（兼容，无强制迁移）。`primary` 是该路径认领组的主入口，优先于条目级标记；陈旧的主入口
  声明在配置期或解析时拒绝，不回落到别的库。页面平时只写声明；用户显式「打开」一个由条目字段关闭的工作区时，页面删除该
  字段，并给其它仍需关闭的注册表工作区补声明。
- **切换主入口 = 替换**：经路径认领、派生或本地派生的工作区，任何入口（附加入口、兜底入口 `personal`）都可「设为主入口」；主入口自身提供
  「更换主入口」，从候选里选另一个库（与「增加附加入口」同一份候选，含新建库）。原主入口**不再挂在该工作区**
  （它的库、卡片、发布方向与其它工作区的挂载都不变）；其余附加入口保留；原本继承祖先路径的工作区被分出来单独认领；
  该工作区关闭的开关不会因切换而打开。保存前提示说明被替换掉的是哪个库。经仓库地址认领的工作区
  不在页面上切换（显式说明，改库的仓库字段），也不再被误当成派生入口。
- **角色始终可见**：工作区下的每一行入口都标注角色（主 / 附），包括只有一行的情形。
- **未声明工作区的开关不再需要落派生主入口**：记忆开关、兜底开关写的是工作区声明，不改变路由，因此
  不再连带声明派生库；只有「挂附加入口」这类真正改变认领集合的动作仍会落派生主入口并说明。
- **卡片浏览的入口跟随工作区**：记忆关闭的工作区下的入口不呈现「打开」，记忆开启的工作区下照常可打开。Host 对直接请求的
  判定不变（按库条目），不接受调用方自报的工作区。
- **记忆开关的生效时机如实写明**：工具即时生效，召回注入与写卡提醒从下一个会话起生效（与现状一致，原规范写成了「已开始的
  会话保持启动时的判定」）。

## Capabilities

### New Capabilities
（无）

### Modified Capabilities
- `dsh-memex-scope`：新增「工作区级决定按路径声明，只能关闭」；路径认领的主入口判定改为「路径声明优先、条目标记兼容」；
  兜底由路径声明或条目字段关闭。
- `dsh-memex-memory`：`memory: false` 可按路径声明（覆盖其下目录），入口级写法兼容读取，任一即关；生效时机如实描述。
- `dsh-memex-settings-ui`：主入口可切换（替换语义）、角色始终标注、开关不再连带声明派生库、remote 认领的工作区只读呈现认领关系。
- `dsh-memex-card-browser`：页面的打开动作按所在工作区呈现；直接请求仍按库条目判定。

## Impact

- `packages/dsh-memex/src/scope/`（settings schema、校验、resolver 的主入口/记忆/兜底判定）、
  `src/host/channel.ts`（试解析报告认领方式与关闭来源）、`src/contract.ts`、`src/client/settings-model.ts` 与
  `page.tsx`、`locales.ts`，以及对应测试。
- 配置：`~/.dsh/settings.yaml` 的 `dsh-memex` 分节新增 `workspaces`；现有条目级字段原样有效，不迁移、不改写。
- 版本：`dsh-memex` 0.2.0 → 0.3.0（配置 schema 新增字段），`dsh.yaml` 与 CHANGELOG 同步。
- 不影响：库目录布局、卡片格式、守门与发布方向、远端动作、召回遥测。
