# Changelog

## 0.1.0 — 2026-11-24

First release. Requires DSH `>=0.2.2-rc.1 <0.3.0-0`, the `dsh-better-sidebar` plugin (`>=0.16.0`) and a Chromium-family browser.

- **A "本地服务" / Local services tab in the right sidebar.** Type `127.0.0.1:<port>`, `localhost:<port>` or `[::1]:<port>` and the frame shows that port of the machine **DSH runs on**, not of the computer your browser runs on. Through Cockpit this means a dev server started on the remote machine opens directly, with no per-port SSH tunnel. The address bar and the page's own scripts see the direct address, never a proxy prefix; a Home button lists the web services found on the Host (port and executable name) and a click opens one.
- **Same-origin Host proxy.** DSH's own web server proxies `/dsh-local-service/…` to the Host's loopback only (`127.0.0.1` and `::1`, never DSH's own port), so it travels over the connection DSH already uses: no new port, tunnel or change to Cockpit. Every request needs the DSH browser session plus a same-origin `Sec-Fetch-Site`; WebSocket upgrades are fenced by the official `Origin`/`Host` check.
- **Dev apps keep working.** Root-path assets and hard-coded cross-port loopback URLs (rewritten by a Service Worker scoped to `/dsh-local-service/`), SPA routing and `location.assign/replace/reload`, links and forms including `form.submit()` and file upload, HMR WebSockets, redirects between loopback ports, cookie login and CSRF tokens read through `document.cookie`, per-port `localStorage`/`sessionStorage` views, and Back/Forward inside the tab, including across different services.
- **Headers and HTML handled carefully.** Only per-port, per-DSH-authority proxy cookies are forwarded upstream; `Origin`/`Referer`/conditional headers are rewritten; framing headers are removed; the injected script goes in before any page script with a CSP nonce (an existing `unsafe-inline` policy is never tightened); compressed HTML is decoded and streamed.
- **Fail closed, best effort.** The tab refuses to load without Navigation API or a working Service Worker, a proxied page cannot register its own Service Worker, and documents that were not injected are blanked. Known exceptions (Workers, nested iframes, scripts parsed before `window.stop()`, the extra GET on cross-document Back/Forward, same-origin trust with DSH, proxy cookies reaching other loopback services of your computer) are listed in the README.
- **Clean removal.** Disabling the plugin removes the Host routes and the index guard and closes in-flight proxied connections; the tab unregisters its Service Worker on unload.
