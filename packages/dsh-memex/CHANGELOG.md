# Changelog

## Unreleased

- **修复：写卡提醒不再把最终回答挤出回合末尾**。此前提醒在回合将要结束时 `inject`，宿主因此在**同一回合**多跑一步，模型被拉回去写卡，回合的最后一条助手消息变成「已记录 N 张卡片」，而真正的回答被折叠在工具调用分组里。现在回合结束时只**排队**，提醒搭乘**后续回合**中第一个本来就要发出的模型请求；回合因此始终以对该回合请求的回答收尾。
- **行为变化**：这一回合之后如果没有新的回合，提醒不会送达，经验也就不会被写成卡片（可接受的代价）。提醒文案本身未改。
- 排队的提醒在送达前若已写卡、记忆被关闭、或会话因压缩/重启而重置召回状态，会被放弃；之后的新召回不继承它。
- 对应 openspec change `dsh-memex-defer-write-reminder`。验证见该 change 的 `design.md`（真实 AgentLoop 集成测试 + 人为破坏实现的突变检查）。
- **内核不可用时说清原因，不再把内部失败码当事实值**。此前内核（全局安装的 `@touchskyer/memex`）缺失时，页面在每个库的展开态显示「远端 不可用 / 详情 `missing`」——用户既不知道缺的是什么版本，也不知道谁来装。现在页面顶部给出「存储内核不可用」横幅，正文包含**需要的版本**与**当前状态**（未检测到 / 检测到 x.y.z），并指出启动器会在下次 `dsh` 启动时自动安装、`dsh doctor` 可立即修复；未知失败码仍原样带出（不猜）。内核健康时不显示任何提示。
- **内核 pin 声明进 manifest**：`dsh.yaml` 的 `dsh-memex` 条目新增 `hostPrerequisites`（`kind: npm-global`, `@touchskyer/memex@0.4.1`），由启动器在启动/构建/重启前自愈（`scripts/host-prerequisites.mjs`；失败只告警不阻塞启动，`DSH_SKIP_HOST_PREREQUISITES=1` 跳过，`dsh doctor [--check]` 手动）。manifest 的 pin 必须等于本包生成物里的 `KERNEL_VERSION`，由 `tests/host-prerequisites.test.mjs` 防漂移。
- 对应 openspec change `host-prerequisite-selfheal`。

## 0.3.0 — 2026-09-29

- **工作区级决定改为路径声明**：配置新增 `workspaces: [{ path, primary?, memory?: false, fallback?: false }]`。声明覆盖该路径下的所有目录，**只能写关闭**，并且与会话怎样被路由无关——改认领、换主入口都不会让声明关闭的地方打开。**关闭优先**：路径声明或主入口条目上的旧字段（`scopes[].memory` / `fallback`）任一关闭即关闭；旧条目字段继续读取，无需迁移。
- **主入口按声明判定**：`workspaces[].primary` 只在声明路径等于最深认领前缀时生效，优先于条目级 `primary: true`；声明的主入口若并未精确认领该路径，配置期拒绝、解析时报错，不回落到别的库。
- **修复开关连带**：此前在 ohmydsh 关闭记忆会连带关掉 dsh-cockpit（两者共用 `personal` 条目，开关写在条目上）。页面现在只写路径声明；一个路径有两个及以上精确认领者时，主入口写在该路径的声明上，而不是条目标记（条目标记会决定该库认领的每一个路径）。
- **可以切换主入口**：「设为主入口」出现在兜底行与附加入口上，主入口自身提供「更换主入口」（与「增加附加入口」同一份候选，含新建库）。切换即**替换**：原主入口不再挂在该工作区（库、卡片、其它工作区的挂载不变），其余附加入口保留；原本继承祖先路径的工作区被分出来单独认领；保存前提示点名被替换的库。经仓库地址认领的工作区不在页面上切换，块内说明原因。
- **角色始终可见**：每一行入口都标注「主 / 附」，包括只有一行的工作区（原来 ohmydsh / dsh-cockpit 的 `personal` 行既不是主也不是附）。
- **页面守门**：任何页面操作都不得悄悄打开一个关闭的注册表工作区。页面在草稿上按 Host 同一套规则重算每个注册表工作区的实际可达性，必要时补关闭声明并在保存前列出；声明盖不过绑定、或补声明会关掉另一个开启的工作区时拒绝并说明。保存时再守门一次。注册表不可用时拒绝保存改变认领的编辑；不对应注册表工作区的配置块只呈现开关状态、不可点。
- **开关不再连带声明派生库**：关闭未声明工作区的记忆或兜底只写一条路径声明；只有真正改变认领集合的动作（挂附加入口）仍会把派生主入口落成声明并说明。
- **兜底可达性如实呈现**：兜底决定关闭但绑定仍让该工作区读写 `personal` 时，兜底行上标注实际可达的方向与绑定名。`resolve` 端点新增 `memory` / `fallback` / `personal` / `claim` / `offBy`。
- **卡片浏览跟随工作区**：记忆关闭的工作区下不呈现「打开」，记忆开启的工作区下照常可打开同一个库；Host 对直接请求仍按库条目判定，不接受调用方自报的工作区。
- **生效时机如实写明**：记忆开关对工具即时生效；召回注入与写卡提醒从下一个会话起生效（行为不变，原规范措辞有误）。
- 保存改为一次带 revision 围栏的 `mutate`，内含 `set ['scopes']` 与 `set ['workspaces']` 两项：旧页面只写 `scopes` 时不会抹掉路径声明。
- **手改配置不拦截**：手改条目仍可能让条目级关闭不再作用于某个目录（0.2.0 的既有行为）。需要稳定关闭的目录，请用路径声明。
- **回滚到 0.2.0**：0.2.0 的 schema 透传未知键，会**忽略** `workspaces`（已用冻结的 0.2.0 schema 测试锁定）。回滚前请：①把需要保持关闭的记忆/兜底写回主入口条目的 `memory: false` / `fallback: false`；②对只靠声明决定主入口、且有两个及以上精确认领者的路径，给主入口条目补 `primary: true` 或删掉多余认领——否则声明关闭的地方会重新打开，这些路径会被 0.2.0 校验拒绝（保留 last-good）。然后 `dsh.yaml` 回退版本 → `node scripts/sync.mjs` → 脱离调用方进程（`setsid`）重启。
- 对应 openspec change `dsh-memex-switch-primary`。

## 0.2.0 — 2026-09-20

- 新增 **Web 半区**：DSH Web 设置面板新增「记忆 / Memory」章节（`settings.section`，id `dsh-memex`，order 25），一行 = 一个记忆库，三列呈现 **工作区 / 记忆库本地路径 / 远端存储**。导航图标用有界 DOM 适配（按可见文案标记自己那一行 + 配对 CSS，自绘 16px 线性 book 作 mask 跟随 `currentColor`），定位失败静默降级为官方齿轮。
- 配置编辑走官方 `ctx.settingsScope`：整份 `scopes` 作为一次带 revision 围栏的 `mutate` 提交，Host 校验与 last-good 语义原样生效；保存以 Host 回读为准。发布方向 **不在页面上**——它是守门的输入，放松守门仍须手改配置。
- 新增 Host 通道 `/dsh-memex`：`stores`（各库存在性/卡片数/远端/自动同步/最近同步/内核版本）、`workspaces`（宿主工作区注册表 + 每个目录当前解析到的路由）与 `resolve`（路径试解析）为**纯查询**，唯一有副作用的端点是用户显式请求的远端动作。通道拿到的是去掉 `ensure` 的窄 scope 接口，接线错误也无法把「打开页面」变成写入；`workspaceRegistry` 是可选注入（`ctx.get`），缺席时端点回答 `known: false` 而不是空清单。
- **页面重构为工作区优先**：页面主语从「配置里声明过的路径」改为**宿主自己的 workspace 注册表**（本机 8 个工作区，其中 4 个此前在页面上不存在、无法挂入口）。每个工作区下列出它的记忆入口：主入口默认为**该路径派生出的库**（先看仓库远端、再看路径末两段），只作为提议呈现、不写配置；入口在列表态只显示角色/名称/卡片数，展开才是路径、远端事实与动作；「+ 增加附加入口」从候选（已声明库 + 命名空间下未声明库 + 新建库）中选择，**重名从构造上不可达**；「关联仓库」这一措辞改为「工作区」。声明了路径但不属于任何工作区的条目仍单独可见可编辑。
- **按工作区关闭记忆**：新增入口级 `memory: false`（缺省开启）。关闭是**完全关闭**——该工作区的会话不注入召回指令、不注入写卡提醒，且 8 个 memex 工具全部拒绝并说明去哪里重新打开；拒绝发生在 `ensure()` 之前，所以关闭的工作区连库目录都不会被创建。开关的粒度是**该工作区的路由**，不是库的全局可达性（`personal` 同时是兜底写入目标，做成全局会连带掐掉其它工作区的兜底路径）；开关按会话启动读取，重新打开无需重启。页面把开关放在工作区标题行，未声明的工作区同样遵循「先落一条声明」的规则。
- **兜底入口语义**：`personal` 从「无绑定时只作为写入目标」改为**默认授予的兜底入口**——默认可读可写，使新工作区零配置可用；由入口自己的 `fallback: false` 关闭，关闭后**读写都不可达**；绑定只做加法（不取消兜底），但绑定显式列出 `personal` 时可以覆盖关闭。给未声明工作区挂入口或关兜底时，页面会**同时把派生主入口落成声明**并在保存前说明：解析器一旦发现任何声明命中该路径就不再走派生分支，只落附加入口会静默抢走路由。
- 远端动作按状态分流：未配置 → `sync --init <url>`；已配置 → `sync` / `sync push|pull` / `sync on|off` / 更换远端（独立动作 + 确认）。**已配置的库从不重新初始化或重建**，系统自身不写库内 `.sync.json` / `.gitignore`。
- **行为变化**：无仓库目录不再 fallback 到 `personal`。按本地路径末两段派生各自的库（`~/Documents/learning` → `documents-learning`），位于同一命名空间且**不配置远端同步**；`personal` 仍是可解析的普通 scope，但不再隐式承接任何目录。已声明路径的路由不变。
- 新增两条**静态**完整性约束：同一库路径被两个 scope 共用、同一 remote 模式字面重复 → settings 校验拒绝并指明两方。remote 模式的**运行时重叠**（正则重叠无法在配置期判定）改为解析时报错，替换原先「按配置顺序第一个命中即生效」的静默行为。
- **同步钩子的失败信息带原因**：写卡后的 `memex sync push`/`pull` 失败此前只报 `exit 1`，实测中一个远端分支保护导致 push 被拒，读者因此要自己进 git 排查。现在信息包含内核 stderr 的首段（折成一行、上限 400 字符），并区分两种后果：push 失败时说明「卡片已本地提交，只是没推上去」，附加库的 pull 失败时说明「写入被跳过」。
- 所有内核调用注入 `LC_ALL=C` / `LANG=C`：内核 `--init` 靠英文错误串判定「remote 已存在」，本机 zh_CN locale 下会让已配置库重跑 `--init` 直接失败（实测 exit 1）。
- 对应 openspec change `dsh-memex-settings-ui`；上一版见 change `dsh-memex-scoped-memory`（0.1.0）。

## 0.1.0 — 2026-09-19

- 首个版本：进程内注册 memex 的 8 个工具、订阅会话生命周期做召回注入与写卡提醒、直接引用内核随包发布的方法论 skill。
- scope 维度：会话 cwd → scope → 独立 `MEMEX_HOME`（统一位于 `~/.dsh-memex/<scope>`），一个库一个 git remote；多库检索并发 fan-out 后按 `(scope 名, 库内原序)` 确定性归并并标注来源。
- 写入 `publish: external` 的库前 fail closed 守门；发布方向未声明按外部处理。
- 存储、卡片格式与 tool description 复用 `@touchskyer/memex@0.4.1`（MIT），不修改上游源码。
- 对应 openspec change `dsh-memex-scoped-memory`。
